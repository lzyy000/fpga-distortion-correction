# 独立的鱼眼畸变处理

更新：2026-10-30。新增功能位于原唯一活动工程，PDS仍是 `pnr_camera_r21_modes/camera_1080p30_raw8.pds`。这是R22上的鱼眼扩展，串口版本仍为 `TUNE v=22`，通过 `fisheye_supported=1` 识别新能力。

## 使用

1. 若PDS中已有旧窗口，先关闭后重新打开。双击根目录 `27_打开R22防抖融合工程.cmd`，在PDS中手动 Generate Bitstream → Rerun All。也可自行运行原02构建入口。此次助手只更新源码与RISC-V固件ROM，没有运行FPGA综合、布局、位流生成或下载。现存旧位流不包含本功能。
2. 用户下载新位流、KEY0复位后，重新启动 `06_相机上位机.cmd`，连接串口。收到带 `fisheye_supported=1` 的TUNE回读后，“鱼眼畸变处理”按钮可用。旧固件上的这个按钮保持禁用，不会误发控制字节。
3. 在“算法调节”开启“鱼眼畸变处理”。启动/复位默认关闭。原“畸变矫正”仍存在、参数与静态核心保持原样；两个镜头模型互斥，打开一个会关闭另一个，避免二次几何矫正。关闭鱼眼不会自动打开原矫正。
4. 双视窗左侧是独立原始帧，右侧是鱼眼结果；关闭双视窗时全屏显示处理结果。滤波、夜景、均衡化和防抖可组合。鱼眼单独开启不要求IMU在线；鱼眼+防抖使用同一次坐标映射和图像采样，防抖仍按原逻辑等待有效IMU或使用安全裁切。
5. 鱼眼开启时，网口抓拍是完整1920×1080鱼眼结果，不含分屏；CRC、补包和取消沿用原机制。抓拍元数据有 `fisheye_applied=true`，不能用这些已矫正照片重新标定原始镜头。原Brown静态矫正单独开启时的网口行为未改。

## 模型与参数

独立工程参数保存在 `firmware/camera_fisheye_calibration.json`，来源为 `calibration/fisheye_local_pc_20261030/fisheye_calibration.json`，14张1920×1080照片、9×6内角点、25mm；训练RMS约0.640像素。

```text
K = [[2660.384218, 0, 666.975649],
     [0, 2671.633081, 380.415713],
     [0, 0, 1]]
D = [-0.067767202, 0.032785618, 0, 0]  # k1,k2,k3,k4
```

这是OpenCV fisheye的theta多项式模型；k3/k4在本轮拟合固定为0。原工程Brown模型的 `k1,k2,p1,p2,k3` 不能与其混用。单独鱼眼的输出内参采用该候选的 `K_prime`（balance=0），可能裁切边缘；联合防抖时沿用防抖裁切参数并使用鱼眼源K。

本轮仍是试算候选：照片元数据记录为处理结果来源，虽然模式均为0；留一法主点漂移明显，固定输出内参的全图采样网格最大位置变化约93像素。用户已要求接入作为独立可切换功能；这不代表标定稳定性或实板效果已通过验收。镜头未更换时使用原矫正；鱼眼镜头使用本开关，并应后续补充明显俯仰倾斜、平整棋盘和独立验证照片。

## 实现

- 模式位bit6=鱼眼；bit0=原Brown、bit1=双窗、bit2=滤波、bit3=夜景、bit4=均衡化、bit5=防抖。新增单字节103开启、104关闭，确认/重试沿用原机制；其它命令保留bit6。
- 每个采集槽锁存鱼眼/Brown/EIS身份；关闭或切换模型只影响后续帧，不取消已采集帧。CPU按带代次令牌的任务提交系数，鱼眼单独开启跳过IMU等待。
- 配置word17的 `0x46495348` 标识鱼眼，word13～16携带四系数；只有显式使能鱼眼的动态映射实例解释此标识。Brown计算分支保留。
- `scripts/export_fisheye_profile.py` 生成独立C头及径向缩放表；公式为 `theta=atan(r)`、`scale=theta/r*(1+k1*theta^2+...+k4*theta^8)`，r=0时scale=1。表覆盖r²=0～8、步长1/128、Q20、线性插值。1024个32位ROM字加一个常量端点，单同步读端口分两次取相邻样本。
- 不复制整帧图像缓存，不扩大原静态32行缓存。复用现有64像素网格、采样缓存、DDR结果槽与Gamma。新增小ROM和插值逻辑；真实资源占用、布局与时序需用户PDS报告确认。
- 图像传输新增几何标记bit2=鱼眼；合法值0/1/3/4/5分别为原路径/EIS/EIS+Brown/鱼眼/鱼眼+EIS。上位机拒绝互相矛盾的标记和混帧。

## 文件与验证

- 新增硬件：`rtl/camera_fisheye_scale.v`、`.vh`、`.hex`。
- 独立参数JSON：`firmware/camera_fisheye_calibration.json`，不覆盖原 `camera_calibration.json`。
- 独立C参数：`night/firmware/eis/fisheye_profile.h`。
- PDS目录下 `camera_fisheye_scale.hex` 是综合隐式ROM输入，必须与rtl副本一致；不能清理掉。源码核对同时包含参数JSON、C头、ROM副本、原Brown头和原网口checksum头。
- 原 `firmware/camera_calibration.json`、`rtl/camera_calibration.vh`、`camera_map_init.v`、`video_row_remap_r21.v` 未改；原位流未覆盖。
- `30_验证鱼眼源码.cmd`：有限坐标、128×96像素、CPU、帧锁存/抓拍与上位机检查，不启动PDS。原28入口也包含新增检查；29入口核对当前ROM和源依赖。
- `reports/fisheye_validation.json`、`fisheye_legacy_targeted_checks.json`、`r22_host_validation.json`、`fisheye_delivery.json` 保存结果。

当前只交付源码及软核初始化文件。没有全1080p并发RTL或新鱼眼实板验收，不宣称达到30fps或最终时序通过。请用户重新构建后先检查原图、原矫正、鱼眼、双窗，再检查鱼眼+防抖与完整帧抓拍。
