# R21 RAM 优化交付

日期：2026-10-25。唯一活动工程仍为 `pnr_camera_r21_modes/camera_1080p30_raw8.pds`。推荐打开 `24_打开R21内存优化版.cmd`，从综合重新运行。原有打开入口均继续指向本工程，并保留工程锁检测。

## 实际修改

- `rtl/camera_snapshot_night_r20.v`：把 CRC/Gamma、DMA发送、CPU读回的三组 RAM 读取合并为一个有使能的同步读端口。CRC/Gamma按原节拍使用保持的256位数据；DMA保留首字预取与take前瞻。CPU载荷读在IDLE获准，若忙时提前读载荷则等待；状态查询与取消命令不依赖该端口。固件原本在分块就绪且非忙状态才读取载荷。一个同步写端口继续由DDR填充和Gamma输出按状态共享。
- `rtl/camera_dma_master_r21.v`：三个16×256位的包缓存各自指定 `syn_ramstyle="select_ram"`。该属性拼法来自本工程现有Pango分布式RAM IP。保留同步读寄存器、包预装载、时序滤波和DDR握手节拍，只改变存储资源实现意图。
- 矫正64行缓存、采集/显示FIFO深度、软核32KiB容量、固件ROM、所有图像数值算法、引脚/时钟约束和布局种子保持原配置。本轮没有新增直方图均衡化。
- 新增4组短抓拍RAM回归，纳入现有验证入口及发布门禁；更新打开脚本。按用户要求，没有为本轮建立历史副本或ZIP。

## 资源目标与验收边界

基线来自本轮修改前的PDS映射：总DRM为130.5/155；抓拍32×256位缓冲因三个读端口形成三份，共12个DRM；DMA三个16×256位包缓存共12个DRM。

结构目标：抓拍12→4，DMA12→0，合计预估节省20个DRM，总数约110.5/155（71.3%）。分布式RAM会增加LUT存储及选择逻辑；PDS是否按目标映射、最终占用和125MHz时序均未实测，不能把预估当成综合结果。重新构建后需检查浅包缓存确实映射为分布式RAM，抓拍缓冲不再出现多份读端口复制。

用户反馈修改前版本上板功能全部通过；修改前最新最终时序报告仍为WNS−0.437ns、TNS−32.865ns、213个setup失败端点。本次资源优化没有宣称修复剩余时序。旧位流、旧映射与时序报告不是RAM优化源码的验证产物。
