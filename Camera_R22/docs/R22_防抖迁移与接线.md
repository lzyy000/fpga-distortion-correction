## 打开和使用

唯一PDS仍为 `pnr_camera_r21_modes/camera_1080p30_raw8.pds`。推荐双击根目录 `27_打开R22防抖融合工程.cmd`。不要打开 `camera-eis-gyro-r27/pnr_camera`；它只是此次迁移的供体。原有01/20/23～26打开入口也转向同一PDS。

在PDS中手动执行 Generate Bitstream → Rerun All，完成后使用新生成的 `pnr_camera_r21_modes/generate_bitstream/camera_1080p_top.sbit`。迁移前留在此路径的位流和绿色勾属于R21，不能代表R22已经编译。手动生成位流后可运行 `29_核对R22工程.cmd` 核对源码和ROM；GUI手动构建的最终时序和实际下载仍需用户核查。脚本构建入口会保存构建前输入冻结并核对新位流/时序时间。

重新启动 `06_相机上位机.cmd`，连接板卡串口115200，收到 `TUNE v=22` 后进入“算法调节”。默认六项均关闭，先打开“双视窗”和“IMU 小抖动防抖”，左侧同帧原始，右侧防抖。KEY0仍复位，KEY1～4不切算法。右侧参数面板支持滚动。

## 基础线路

| 信号 | FPGA位置/接口 | 本次处理 |
|---|---|---|
| WT901C TTL TX → imu_rx | U22，ATK J1-7 / LA18_P_CC | 新增顶层输入与LVCMOS33约束，独立115200 8N1接收 |
| IMU GND ↔ 板卡GND | 按板卡GND丝印连接 | 必须共地，沿用原已验证接线 |
| IMU电源 | 沿用当前已验证供电 | 本次没有更改供电；U22只是输入信号脚 |
| 板卡USB串口RX/TX | B24 / C24 | 保留，PC控制和日志共用原CP210x串口 |
| OV5640 / HDMI / DDR3 / RGMII | 原工程接线 | 保留全部原引脚和时钟配置 |

U22为3.3V FPGA输入，使用TTL输出；RS232电平不能直接接入。当前只接收IMU，不从FPGA向IMU发配置指令。保留用户当前100Hz、115200、98Hz设置假定；保留0x52角速度和0x59四元数输出，0x51加速度用于静止检测；实际是否持续收包以上位机的IMU数据年龄和诊断为准，不根据截图中的“读取配置失败”把设置当成实测。

用户确认外壳安装：+X朝画面右侧，+Y向上，−Z朝拍摄方向。实际串口回传轴已通过水平摇头记录校验，不能再直接用外壳轴替换回传轴：

```
摄像机坐标下角速度 = [回传X, -回传Z, 回传Y]
摄像机→回传IMU坐标 B = [1 0 0; 0 0 1; 0 -1 0]
```

供体18秒摇头记录中，去偏置角速度能量约99.07%在回传Z轴。用户已确认这套映射使左右明显改善、拉扯减轻，并且上下防抖和画面方向仍正常。原始证据副本见 `reports/r22_eis_axis_evidence.json`；这是供体的标定证据，不是融合版本的上板报告。

## 参数与算法

| 上位机参数 | 默认 | 作用 |
|---|---:|---|
| 裁切倍率 | 1.18 | 基准裁切，范围1.05～1.60；倍率越小，边界可用余量越小 |
| 上下/滚转平滑 | 250ms | 保留已验证的上下补偿 |
| 左右平滑 | 500ms | 保留已验证的水平轴映射和较慢的yaw虚拟轨迹 |
| 卷帘修正 | 100% | 基于源行的水平yaw近似，设0可对照 |
| 画面时刻偏移 | 0ms | 保留用户优于16ms的选择，尚非曝光中心精确标定 |
| IMU延迟 | 0ms | 包到达时间与实际采样时刻偏差的校准量 |

卷帘读出时间在硬件测量第一行与最后一行首像素间隔，逐帧保存。供体约32.482ms，融合版本以上板回读为准。采用陀螺逐样积分、帧时刻插值、短弧四元数平滑、裁切边界退让；不锁绝对地平线，静止任意初始姿态的相对映射保持正常方向。安全边界策略和极端姿态的备用裁切沿用供体，基准1.18并非所有极端动作下的绝对倍率上限。

这是IMU旋转分量的电子防抖。横向/上下平移、近景视差和运动模糊不在该模型的可完整消除范围。卷帘修正仅为受限、小角度、帧内近似恒定yaw角速度模型，不宣称完整三轴卷帘、加速度或畸变场估计。

## 功能组合

| 功能 | 防抖关闭 | 防抖开启 |
|---|---|---|
| 镜头畸变矫正 | 保留原静态稠密映射引擎 | 在同一次源坐标映射中叠加Brown镜头模型，避免二次图像重采样 |
| 双视窗 | 左原始/右所选处理，960×540预览 | 同一布局，右侧选防抖结果，左侧始终独立原始帧 |
| 滤波 | 保留空间/时间滤波与0～100%强度 | 同样先滤波后防抖 |
| 夜景 | 原有按帧Gamma及强度 | 防抖双线性采样后执行一次Gamma，HDMI/抓拍不重复叠加 |
| 全局均衡化 | 保留全局统计与强度 | 同样先均衡化后防抖 |
| 网口抓拍 | 保持R21行为：滤波/夜景/均衡化，不含静态几何或双窗 | 复制被锁定的完整1920×1080防抖结果；可包含同时开启的镜头矫正，始终不拼双窗 |

“防抖开、镜头矫正关”时使用零Brown系数的针孔补偿，不暗中强制开启镜头矫正；原畸变较大时边缘防抖精度受近似影响。需要同时改善镜头畸变时显式打开矫正。

开关在取得帧槽时锁存；已接收的帧完成后才被后续新模式帧替换，切换存在几帧流水延迟。抓拍冻结期间继续保持原槽所有权，结束后释放；IMU不足时生成相对固定映射并在上位机提示等待IMU，避免无法出帧。

## 关键实现

- `rtl/camera_1080p_top_r21.v`：仍为唯一顶层，接入新模块；原DDR写优化、时钟和网口保留。
- `rtl/camera_eis_serial_r22.v`：独立IMU UART、WIT 0x51/52/53/59解析、64条陀螺FIFO与微秒包时间戳；原控制字节使用16条FIFO。
- `rtl/camera_capture_eis_r22.v` / `camera_eis_jobs_r22.v` / `camera_eis_manager_r22.v`：四槽帧租约，SOF、逐帧读出时间、代次令牌、四组28字参数银行，拒绝旧代次提交。
- `rtl/camera_eis_remap_r22.v`：原生全帧31×18几何网格、64KiB四银行采样缓存、定点流水乘除、双线性插值；与静态引擎共享原批量DDR端口。卷帘单独越界先关该帧卷帘重试，仍失败才用安全矩阵。
- `rtl/camera_snapshot_eis_r22.v`：按锁定的EIS帧地址抓拍，避免二次Gamma，保留整帧/分包CRC、取消和重试。
- `night/firmware/camera_r22_main.c` 与 `eis/*.h`：保留相机寄存器初始化/强制回读、网口服务，优先处理陀螺和帧解算，运行时日志使用非阻塞环形缓冲。
- `rtl/image_cpu_r22.v`：CPU总物理存储64KiB；8KiB数据/栈窗口0x0000～0x1fff，56KiB代码窗口0x10000～0x1dfff，保留旧外设地址。链接保留2KiB栈。
- 上位机：现有协议兼容R19/20/21；仅在R22确认后启用EIS，参数逐包确认/重试，旧固件不会收到新二进制命令。

DDR分区保留：处理源帧0x01000000、抓拍0x02000000、静态映射0x03000000、结果帧0x04000000、时间滤波历史0x05000000、独立原始帧0x06000000。每槽4MiB；防抖直接使用现有四组源/结果槽，不另占整帧缓存区。

MMIO：IMU与主机路由0xac00～0xadff；EIS核心0xb200～0xb2ff；快照0xb100～0xb17f及0xb400～0xb7ff；网口0x9000及0x9800～0xa7ff。系数28字写0xb200～0xb26f，作业令牌/时间0xb2b0/0xb2b4，先写令牌0xb2b8再提交版本0xb280，提交时才复制到匹配代次银行。

旧单字节命令保留：0～100滤波强度、128～228夜景、112～127原四模式、248/249均衡化开关、GHE分段强度、240查询；新增101/102为EIS开/关。二进制参数帧 `FF 45 op len seq payload checksum` 与旧命令在硬件隔离，op8裁切/平滑、11水平平滑、12卷帘、10时刻校准。CNP1 DATA包flags bit0=EIS结果、bit1=同时做了镜头矫正，主机保存到照片JSON并拒绝不同flags的混帧。
