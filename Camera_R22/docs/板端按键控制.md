# 板端短按 / 长按控制

2026-10-31，按用户更正后的分配实现。KEY0 保留原系统复位电路；此前中断步骤的 KEY0 功能键 / KEY2 复位方案已撤回。

| 按键 | 短按并松开 | 长按 |
| --- | --- | --- |
| KEY0 | 系统复位 | 保持复位，松开后重新初始化 |
| KEY1 | 夜景开关 | 全局直方图均衡化开关 |
| KEY2 | 普通 Brown 畸变矫正开关 | 鱼眼畸变处理开关 |
| KEY3 | 旋转稳像开关 | IMU 小抖动防抖开关 |
| KEY4 | 滤波开关 | 双视窗开关 |

- 同一个操作再次执行即关闭。短按在松开并消抖后生效；稳定按下达到800ms后触发一次长按，继续按住不连发，松开不再触发短按。消抖20ms，使用125MHz核心时钟的毫秒使能，不创建新时钟。
- 复位或上电时已按住的功能键，要先松开才能重新触发，防止启动时误切换。
- 普通畸变 / 鱼眼互斥，旋转稳像 / 小抖动防抖互斥。开启其中一项会关闭同组另一项；关闭时不会自动开启另一项。其他功能仍可组合。
- 功能键只更新原模式寄存器，不改变滤波、夜景、均衡化强度，也不写入两套稳像参数。所有参数调节继续通过上位机。
- 图像处理仍在原帧边界生效。按键不会重置采集、DDR、IMU或网络；KEY0系统复位行为保持原样。

## 与上位机配合

板端和串口共用同一个模式寄存器。上位机沿用现有约2秒一次的查询显示板端状态；无需修改固件ROM或通信格式。已修复查询后把旧模式自动写回的问题。若上位机正在编辑部分开关，查询回读时发现板端切换，未编辑的其他位会合并回读状态，上位机不会一直卡在“确认中”。

同一核心周期恰好同时出现串口模式写和按键事件时，先采用合法的串口模式，再应用该按键切换。主机发送中的幂等命令仍可能重试，因此串口整组模式写入等待确认时，同组按键的再次切换可能被重试覆盖，因此同时操作时应等待串口回读确认最终状态。

KEY0仍位于C22；KEY1 C23、KEY2 B22、KEY3 A22、KEY4 B20，均沿用现有管脚约束，无需改线。

- `rtl/camera_1080p_top_r21.v`：按键映射和与原串口模式写的统一仲裁。像素处理、DDR调度和算法参数路径保持原实现。
- `rtl/image_cpu_r22.v`已恢复为修改前字节一致的KEY0复位实现。PDS、FDC和固件ROM未改。
- 上位机 `tuning.py` / `console.py` 接受并合并板端回读。
- `33_验证板端按键.cmd`：有限按键/复位RTL、144种模式、快照身份、上位机和ROM依赖核验，不执行综合、布局布线或下载。
- 结果在 `reports/board_keys_delivery.json` 和 `board_keys_validation.json`；修改前基线在 `work/board_keys_20261031/baseline`。

需由用户重新综合、布局布线、生成位流并下载后，板端按键才会生效。未将源码仿真结果当作实际时序、帧率或画质验收。新增的是少量寄存器和控制逻辑，实际资源以用户的新综合结果为准。
