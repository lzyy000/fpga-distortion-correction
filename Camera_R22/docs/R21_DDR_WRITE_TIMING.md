## 修改原理

引擎数据原本已在 `E_LOAD -> write_sample -> filtered_block -> filtered_q` 中预装完整的最多16拍子突发，经 `E_DRAIN` 提交末拍后才进入 `E_WA/E_WD`。采集数据已在 `T_LOAD` 进入原始/处理缓冲，随后用 `raw_q/filtered_q` 写出。CPU写数据和掩码在IDLE接收请求时锁存。

旧输出选择器仍保留 `owner==1 ? eng_wdata : owner==2 ? cap_head[255:0] : cdata`。这两个直通分支不承担有效原生写拍，但在空闲、地址和预装阶段形成上游请求/数据到DDR数据总线的组合路径，静态时序仍分析它们。

新选择器只有：`RAW_W -> raw_q`、`T_WH/T_WC/E_WD -> filtered_q`、其余状态 `cdata`。所有源都是已寄存的数据。`WD` 仅由CPU的 `WA` 进入；引擎使用 `E_WD`，采集使用 `RAW_W/T_WH/T_WC`。没有增加周期或寄存器级，没有改变有效写入的数据、地址、掩码、完成条件和突发边界；地址/空闲周期数据允许变化，因为DDR不在这些周期消费数据。
